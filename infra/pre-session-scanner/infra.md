# Pre-session scanner — Infrastructure

AWS deployment for the pre-session scanner's backend. A single Lambda
(container image) fronted by an API Gateway HTTP API, with two routes:

**`POST /scan`** — runs `pre-session-scanner/scanner.py`'s `build_result()`
live (no scheduling yet — this is Phase 1, on-demand only) and returns the
same JSON the CLI prints, plus a written report generated by Claude (see
below). Request body: `{"run_type": "on-demand"}` (optional, defaults to
`"on-demand"`). On success, the full result — including the report — is
saved to the archive bucket (see below).

**`GET /archive`** — lists the most recent saved scans (up to 50, newest
first) from the archive bucket, each with its full result including the
report. No pagination yet — fine at this volume (a personal, manually-
triggered tool), revisit if that changes.

No frontend of its own — it's called from the Cloudfolio site's
"Pre-session Scanner" and "Archive" tabs (`infra/cloudfolio/frontend/index.html`),
which hardcode this stack's API URL as `PRESESSION_API_URL`. **If this stack is
ever destroyed and recreated, update that constant** — unlike cloudfolio's
own `__API_URL__`, it isn't injected at deploy time (deliberately, to avoid
coupling the two tools' deploy processes together).

## Report generation (Claude API)

After a successful scan, `pre-session-scanner/report.py` sends the result
to Claude (`claude-haiku-4-5`) and asks for a short written report — see
that file's system prompt for exactly what it asks for, including the
"likely near-term bias" call (an explicit, documented exception to the
design doc's no-verdict principle — see the Amendment in
`pre-session-equity-tool-design.md`). Failure is non-fatal: the scan still
returns successfully with `report_error` set instead of `report`.

The Anthropic API key lives in AWS Secrets Manager
(`pre-session-scanner-anthropic-api-key`), read by the Lambda at request
time (`_get_anthropic_api_key()` in `lambda_handler.py`, cached per warm
container). Terraform creates the **empty** secret only — the value is set
out-of-band so it never lands in Terraform state or git:

```bash
aws secretsmanager put-secret-value \
  --region eu-west-2 \
  --secret-id pre-session-scanner-anthropic-api-key \
  --secret-string "sk-ant-..."
```

Run that yourself (e.g. via Claude Code's `!` prefix) rather than pasting
the key into a chat transcript.

## Report archive (S3)

Every successful scan is saved to a private S3 bucket
(`pre-session-scanner-archive-<account_id>`), one JSON object per scan at
`{date}/{timestamp}-{run_type}.json`. This bucket has **no `force_destroy`**
— unlike the site buckets, it's meant to accumulate, so `terraform destroy`
will refuse to remove it while it holds objects rather than silently
wiping saved report history. Archiving a scan is best-effort: a failure
there doesn't fail the scan response (logged to CloudWatch instead).

## Deploy

No CI yet — deploy locally:

```bash
cd infra/pre-session-scanner/terraform
terraform init -reconfigure \
  -backend-config="../../backend.hcl" \
  -backend-config="key=pre-session-scanner/terraform.tfstate"
terraform apply -target=aws_ecr_repository.app -auto-approve

# from repo root — build reuses pre-session-scanner/*.py directly, see Dockerfile
ECR_URL=$(terraform -chdir=infra/pre-session-scanner/terraform output -raw ecr_repository_url)
aws ecr get-login-password --region eu-west-2 | docker login --username AWS --password-stdin "${ECR_URL%%/*}"
docker build --platform linux/amd64 -f infra/pre-session-scanner/app/Dockerfile -t "${ECR_URL}:latest" .
docker push "${ECR_URL}:latest"

cd infra/pre-session-scanner/terraform && terraform apply -auto-approve
```

(Note: unbraced `$ECR_URL:latest` breaks under zsh — it gets parsed as a
history-modifier suffix (`:l` = lowercase) rather than a literal colon.
Always brace it: `${ECR_URL}:latest`. Bash doesn't have this problem, but
these are typed ad hoc, not run via a `.sh` script, so it matters here.)

## File structure

```
infra/pre-session-scanner/
  app/
    Dockerfile           Lambda container image (Python 3.12)
    lambda_handler.py    Routes GET /archive and POST /scan; calls scanner.build_result(),
                          report.generate_report(), archives to S3
    requirements.txt     yfinance, pandas, numpy, anthropic
  terraform/
    backend.tf           S3 remote state config (bucket/region from ../../backend.hcl)
    variables.tf          aws_region, project name
    main.tf               ECR, IAM, Lambda, API Gateway, Secrets Manager secret, archive S3 bucket
    outputs.tf             api_url, ecr_repository_url
```

The Docker build copies `pre-session-scanner/{scanner,dashboard,report}.py`
and `watchlist.json` directly from the repo root into the image — the
Lambda runs the *same* code as the CLI, not a reimplementation of it.
`dashboard.py` is copied because `scanner.py` imports it at module load
time, even though the Lambda handler only calls `scanner.build_result()`,
not the file-writing `dashboard.write()`.

## Lambda notes

- **Memory**: 512 MB (no matplotlib/chart rendering here — the site's charts
  are client-side SVG built from this JSON, not server-generated images)
- **Timeout**: 180s — roughly 4 sequential `yfinance` calls per watchlist
  ticker (breadth, screener, news, calendar) plus VIX and oil/gold (incl.
  90-session price history); no batching yet, matching `scanner.py`'s
  CLI-simple style
